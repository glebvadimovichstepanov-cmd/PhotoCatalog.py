# PhotoCatalog 2.1

![PhotoCatalog desktop](docs/desktop-preview.png)

PhotoCatalog — локальный каталогизатор фотографий и видео для Windows с аккуратным графическим интерфейсом. Он раскладывает медиатеку по годам и дням, проверяет каждую копию по SHA-256 и сохраняет оригиналы на месте.

![Интерфейс PhotoCatalog](docs/desktop-preview.png)

## Что нового

- Готовый `PhotoCatalog.exe`: Python, Qt, Pillow, pymediainfo и MediaInfo.dll внутри одного файла.
- Предпросмотр без записи, прогресс, журнал результатов, остановка и экспорт JSON.
- Разные файлы с одинаковым временем больше не перезаписываются.
- Защита от ZIP traversal, ссылок, Windows-зарезервированных имён, ZIP-бомб и повреждённых архивов.
- Тёмная боковая панель, светлая рабочая область и понятный сценарий из трёх шагов.

## Быстрый старт

1. Скачайте `PhotoCatalog.exe` из GitHub Releases и запустите двойным щелчком.
2. Выберите источник и отдельную папку назначения.
3. Нажмите «Предпросмотр», проверьте план, затем «Начать копирование».

EXE не требует установленного Python. Приложение не использует облако и не отправляет фотографии в интернет.

Для разработчиков сборка выполняется на Windows:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
.venv\Scripts\python.exe -m pip install -e . --no-deps
.venv\Scripts\python.exe tools/build_windows.py
dist\PhotoCatalog.exe --self-test dist\self-test
```

`PhotoCatalog.exe.sha256` содержит контрольную сумму готового файла. Self-test запускает GUI в скрытом режиме, проверяет предпросмотр, копирование, повторный запуск, сохранность исходника и MediaInfo, затем создаёт `desktop-preview.png`. Для диагностики Self-test запускается с ключом `--self-test`; обычный запуск всегда показывает только окно приложения.

Для командной строки остаётся `python -m photocatalog`; графическая команда после установки — `photocatalog-desktop`.

Каталогизатор фото и видео для Windows, Python 3.12+. Проверенная среда: Windows x64, Python 3.12.14.

Программа сохраняет оригиналы, проверяет копии по SHA-256 и никогда намеренно не заменяет существующие файлы. Два разных снимка с одинаковой датой сохраняются оба. Повторный запуск пропускает проверенное совпадение в соответствующей группе имён.

## Установка (PowerShell)

Из распакованного каталога проекта:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
.venv\Scripts\python.exe -m pip install -e . --no-deps
.venv\Scripts\python.exe -m photocatalog --help
.venv\Scripts\python.exe -m photocatalog --check-mediainfo
```

requirements-windows.txt фиксирует проверенные Pillow и pymediainfo. Минимальная установка без анализа видео: `python -m pip install .`. Для опционального видео: `python -m pip install ".[video]"`. Отсутствие pymediainfo или DLL не мешает CLI и обработке фото; видео используют mtime с предупреждением. tqdm больше не требуется.

DLL, поставляемая Windows-пакетом pymediainfo, используется по умолчанию. Старая MediaInfo.dll оставлена в репозитории для совместимости, автоматически из текущей папки не подгружается. Для явного выбора:

```powershell
.venv\Scripts\python.exe -m photocatalog --check-mediainfo --mediainfo-lib "C:\Tools\MediaInfo.dll"
```

## Запуск

```powershell
# План без создания папок и распаковки:
.venv\Scripts\python.exe -m photocatalog "C:\Свалка" "D:\Фото" --dry-run

# Копирование и новый JSON-отчёт:
.venv\Scripts\python.exe -m photocatalog "C:\Свалка" "D:\Фото" -w 4 -b 50 --report "D:\Отчёты\catalog-run-01.json"

# Быстрый режим видео и исключение ZIP:
.venv\Scripts\python.exe -m photocatalog "C:\Свалка" "D:\Фото" --fast-video --no-extract-zips

# Интерактивный режим:
.venv\Scripts\python.exe -m photocatalog --interactive
```

Также доступен `python main.py ...` после установки пакета и команда `photocatalog ...` в активированной среде. Без аргументов и настроек команда показывает ошибку использования, а не начинает обработку стандартных папок.

Пример результата: `2020/2020-02-03/2020-02-03_04-05-06_снимок.jpg`. Дробная часть секунды добавляется, если известна. При конфликте содержимого добавляется суффикс SHA-256 и при необходимости счётчик. Разные оригинальные имена сохраняются; глобального удаления дубликатов всей коллекции нет.

## Параметры и настройки

CLI имеет приоритет над окружением:

| Переменная | По умолчанию |
|---|---|
| PHOTOCATALOG_SOURCE | обязательно указать |
| PHOTOCATALOG_DESTINATION | обязательно указать |
| PHOTOCATALOG_WORKERS | 4, допустимо 1–64 |
| PHOTOCATALOG_BATCH_SIZE | 50, положительное число |
| PHOTOCATALOG_MEDIAINFO_LIB | библиотека из установленного пакета |
| PHOTOCATALOG_ZIP_MAX_FILES | 10000 элементов на архив |
| PHOTOCATALOG_ZIP_MAX_BYTES | 10737418240 байт на архив (10 GiB) |
| PHOTOCATALOG_ZIP_MAX_RATIO | 1000 |

Лимиты переопределяются флагами `--zip-max-files`, `--zip-max-bytes`, `--zip-max-ratio`.
`--no-fast-video` имеет приоритет над `--fast-video`.
`--verbose` включает подробную диагностику. Паролей, токенов и сетевых сервисов в приложении нет.

Источник и назначение не должны совпадать или содержать друг друга. Корневые пути через symlink/junction запрещены; ссылки внутри источника пропускаются с записью причины в отчёт.

Статусы: copied, duplicate, planned, skipped, error. В JSON сохраняются исходный путь (для ZIP — архив!элемент), целевой путь, ISO-дата с известным поясом, источник даты, SHA-256 для проверенного результата, предупреждение/ошибка. Отчёт создаётся только новым файлом вне источника. `--dry-run --report` запрещён, поскольку отчёт пишет на диск; dry-run выводит JSON в stdout.

Коды выхода: **0** — обработка без ошибок (в том числе пустой источник), **1** — ошибка IO/частичный результат/недоступная MediaInfo при диагностике, **2** — некорректные параметры, **130** — Ctrl+C. Fallback метаданных и пропуск ссылок отражаются предупреждениями, но не считаются ошибкой копирования.

## Тесты и стиль

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
```

Если системная временная папка недоступна, используйте `--basetemp=.pytest-local/run-01` с отдельным новым путём. pytest очищает выбранный basetemp: не указывайте каталог с пользовательскими данными.

Тесты используют искусственные файлы и проверяют конкуренцию, повторный запуск, сохранность исходника и ранее записанного результата, ошибки копирования/метаданных/ZIP, dry-run, коды выхода, реальные EXIF и CLI через subprocess. CI настроен на Windows/Python 3.12 и 3.13; успешный локальный прогон не означает, что удалённый CI уже выполнен.

## Архитектура и ограничения

```text
src/photocatalog/
  cli.py        параметры, окружение, итоговые коды
  catalog.py    координация, ограниченные пачки, результаты
  storage.py    границы путей, хеши, публикация копий
  archives.py   проверка ZIP и ограниченная распаковка
  metadata.py   Pillow, MediaInfo и разбор дат
tests/          проверки поведения
docs/behavior.md правила сохранности и восстановления
```

Используется пул потоков для IO с ограничением размера пачки; обращения MediaInfo сериализованы из-за общего состояния нативной библиотеки. Это упрощает Windows-запуск и исключает передачу неинициализированной DLL-конфигурации между процессами.

HEIC/RAW распознаются как кандидаты для копирования, но извлечение EXIF зависит от возможностей Pillow; при отсутствии декодера используется mtime с предупреждением. Проверка SHA-256 подтверждает равенство копии исходным байтам, а не исправность медиафайла. Уже повреждённый оригинал может быть скопирован без изменения.

Подробнее: [правила поведения](docs/behavior.md), [проверка версии](docs/validation.md).
